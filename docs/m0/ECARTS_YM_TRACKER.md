# Deviation table YM-Tracker → STYM2149 (§5, reference added by Indus on 13/10/2026)

Rule (§9, the same as the one applied to maxYMiser and TTrak): only functions are taken over, from what the site shows or documents publicly (labels, help, visible texts). No JavaScript file or code repository was read; no screen, graphics, demo song, sample or data is taken over. A function only hinted at by a label is noted as such and marked "to be clarified".

**Sources consulted on 13/10/2026** (WebFetch tool, which returns an automatic summary of the page with short quotes, about 125 characters per excerpt; twelve calls in all)
- [YT] Home page `https://ym-tracker.lovable.app/`, read three times: title "YM-Tracker", subtitle "Atari ST · YM2149 · FT2 keys · v0.1.0", meta description "A FastTracker 2-style web tracker for the Atari ST YM2149 sound chip." and "Inspired by Arnaud Carré's MaxYMiser.", labels of the buttons and panels, keyboard legend shown on the page.
- [YC] Page `https://ym-tracker.lovable.app/config`, the only internal link exposed by the home page ("⚙ Config" button, tooltip "Open config (chips, digidrum, paths)"): sections "Hardware", "Default paths" and "Backup".

- [YI] Four screenshots of the instrument tabs "Tone", "HardEnv", "Waveform" and "Macros", sent by Indus in the project thread on 13/10/2026: only the labels, the values shown and the help texts are noted from them; the screenshots are neither versioned nor reproduced (§9).
- [YA] The application itself, displayed version "v0.1.0", used on 13/10/2026 (06:55-07:20 UTC) in headless Chromium, at Indus's request (« Peux-tu utiliser YM-Tracker pour comprendre à quoi servent Phase, Duty, Noise AND et OR, Channel mode et Sinus-SID ? » ("Can you use YM-Tracker to understand what Phase, Duty, Noise AND and OR, Channel mode and Sinus-SID are for?")): visible texts, tooltips, field bounds, preview drawn by the application, and audio output of the "▶ Audition" button and of the ▶ buttons of the FX panel, recorded then measured. Code and sources not read; no screen, graphics, data or sample taken over; no hardware value drawn from the application.

**What could not be read**
- The addresses `/docs`, `/doc`, `/fx`, `/help`, `/about`, `/manual`, `/sitemap.xml` and `/robots.txt` all returned the error "There was an error while fetching"; they probably do not exist as public pages.
- The effect sheet ("FX" button), the documentation ("DOC" button) and the shortcuts window ("?" button) are not in the content received by WebFetch: only their labels are there, since the application produces these texts on a click. They were read afterwards by using the application [YA], without reading its code; only short quotes are taken from them (Y13, Y14, Y35, Y37 to Y41). The content of the instrument tabs, also absent from the page, is known from Indus's screenshots [YI].
- The formats `.ymtrk.json` (song), `.ymi.json` (instrument) and `.snd` are documented nowhere on the site: not read.

**Nature of the reference.** YM-Tracker is a web application at version 0.1.0 (its metadata name Lovable as the author of the page), which calls itself "FastTracker 2-style" and inspired by maxYMiser. It is not a native Atari ST tracker: it serves as a reference for ergonomics and functions, never for hardware behaviour; no hardware value is drawn from it. Its meta description credits maxYMiser to Arnaud Carré, while §5 of STYM2149_SPEC.md credits it to gwEm; this changes nothing in the table.

Prototype status: **Abs** = absent, **Part** = partial, **Yes** = present (P ids of PARITE.md). Milestone: M6 unless stated. When a function overlaps a row of ECARTS_MAXYMISER_TTRAK.md (X for maxYMiser, T for TTrak), it refers to that row instead of being duplicated.

## To be clarified

1. Format of the `xx` parameters of the commands (Y13) and mapping to the letters of maxYMiser (`X`, `P`, `S`, `Z` do not have the same meaning), to be decided with Q8.
2. In the instrument tabs: effect of "Phase" (Y37), of "Duty" (Y38), of "Noise AND" and "Noise OR" (Y39), none in the sound of YM-Tracker v0.1.0; modes 5 and 7 of "Channel mode" (Y40); meaning of "Auto N" and "Auto D", inferred divisor (Y35); playback of a digidrum at its own frequency (Y34); whether the pitch macro adds up or not (Y42).
3. Rest of the DOC (Y14): only the passages useful for Y13, Y14, Y35 and Y37 to Y41 were read.
4. Octave keys: "F1–F7" in the legend, "F1–F8" in the toolbar (Y7).
5. Role of Shift in "Ins/⇧Ins" and "Bksp/⇧Bksp" (one channel or all channels), and meaning of "delete prev" (Y12).
6. Scope and step of "Transp." in the Song menu (Y17).
7. Relation between "BPM" and "Spd", and duration of the tick used by the ADSR, the macros and the arpeggio speed (Y6, Y20, Y24, Y33).
8. Nature of the `.snd` extension and structure of the `.ymtrk.json` and `.ymi.json` formats (Y19, Y27).
9. Mapping applied by "Import .xm": channels, instruments, samples and effects (Y26).
10. Meaning of the indicator shown after "Caps =" in the toolbar (Y5).
11. The demo titles "Slides & Vibrato", "Volume Effects", "Flow Control", "YM Envelopes", "Note Off / ADSR" and "YM6 FX Showcase" name families of functions that the site does not describe; "YM6 FX" means, according to the HardEnv tab, the commands `Q`, `S`, `U` and `Z` (Y13). No other row of the table is drawn from them.
12. Octave numbering: C-5 is 261.5 Hz in YM-Tracker (Macros tab), while the prototype calls the MIDI note 60 C4 (261.63 Hz; `viewAbsBase`, "48 = C3"). The tracker view (M6) and the XM import (M7) will have to fix a convention.
